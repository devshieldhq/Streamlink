Quick start

StreamLink XR is one service: a relay server that fans your stream out to each platform through its own FFmpeg process, and also serves the website and the two client pages below from the same process. There's nothing else to deploy separately.

Prerequisites

Node.js 18+ and FFmpeg installed where the server runs (handled automatically if you deploy with the included Dockerfile), plus stream keys for whichever platforms you want live.

1. Start the server

cd streamlink-server npm install npm start

To enable the real AI agent rather than its deterministic fallback, set your key first:

export ANTHROPIC_API_KEY=sk-ant-... npm start

2. Serve it over HTTPS

Camera access, the microphone, and (for the VR room) WebXR and hand tracking all require a secure context. localhost is exempt for local testing, but a phone or a Quest on your network isn't — deploy it (Render, with the included render.yaml, works out of the box) or use a tunnel like ngrok.

3. Pick an entry point

  • /live — a normal web page. Works on a phone, laptop, or any browser. Grants camera/mic access, add your platform keys, press Go Live.
  • /app — the VR control room. Opens on the Quest browser only (WebXR doesn't run on phones, and not at all on iOS Safari) — same backend, hand-tracked control instead of a flat page.

Either page captures your camera and microphone directly in the browser (getUserMedia + MediaRecorder) and streams encoded chunks to the server over HTTP as you go — nothing is sent anywhere before you grant that permission.

The AI agent

Press the talk button or say a command out loud — for example, "Twitch dropped, fix it and lower quality if needed." The agent checks live stream health, reconnects the affected platform, checks again, and only changes quality if the numbers still show trouble. Each step appears on the agent pipeline panel as it happens.

Without ANTHROPIC_API_KEY set, the server runs a deterministic fallback that performs the same sequence for common commands (start, stop, reconnect a platform, raise or lower quality) — useful for testing without an API key, though it isn't the model doing the deciding.

FAQ

Why does one platform need a URL and not just a key?

Vimeo, LinkedIn Live, X Live, and Rumble issue a fresh ingest URL for each event rather than reusing one fixed address, so there's nothing to hardcode on the server for those.

Does a dropped platform affect the others?

No — each platform runs its own FFmpeg process. Reconnecting one restarts only that process; the rest keep streaming the whole time.

Do I need hand tracking enabled?

No. Controllers work as a laser-pointer fallback if hand tracking isn't on.

Troubleshooting

The page won't enter VR

Check that it's served over HTTPS (or localhost) — WebXR refuses to start otherwise.

A platform stays on "connecting"

Double-check its key or URL in the lobby — some platforms' keys expire and need regenerating.

Voice commands aren't picked up

Your browser needs Web Speech API support and microphone permission granted to the page.
